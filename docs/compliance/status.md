- **Table subscript access `t[key]` (spec `docs/spec/03-declarations.md` `t["age"] = 33 # valid; equivalent to t.age`; referenced by `docs/spec/05-operators.md` "ordinary dynamic table access (`t[key]`)"):** ✓ **implemented + verified Round 51** (found 2026-11-05, Round 50; the `[x] table member read/write t.name, t["age"]` bullet above had been claimed before it ever worked). Empirically it used to throw `type error: cannot subscript non-array value` / `cannot assign into non-array value`: the compiler emitted `ARRGET` (read) / `ARRPUT` (write) for **every** subscript and both VM handlers accepted `Type::Array` only, while `TABGET`/`TABPUT` — which already dispatch through `ObjectOps::getField`/`setField` — were reachable only from the `.` member path.
